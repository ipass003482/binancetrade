# Kev 訂單流 Demo

`kev-order-flow-v1` 由使用者明確要求取代五分 K／Kronos 候選路徑。現貨提供各幣買入；合約提供每幣多空；Kev／Codex 選一個 pair/action 或 HOLD。候選只有資料、成本、尺寸、冷卻、持倉與曝險檢查，没有方向預篩。

目前 Kev 使用 `decisionStyle: balanced`。撤回先前「中等把握也優先成交」提示；必須先考慮可成交退出價格是否有足夠理由跨過費用及緩衝，弱訊號可 HOLD。固定停利只是情境，不能拿它當預測來證明正期望值。固定停損、停利、單筆壓力風險、曝險上限、原生保護與一分鐘期限保留。

每個候選新增 `kev-executable-cost-v1`：以 100 USDT 名義部位計算可成交買／賣價、雙邊 taker 費率、雙邊滑價、資金費保留、退出損平價、含淨利緩衝退出價，以及固定停利／停損與行情不動時的淨額。它不是帳戶金額或報酬預測。現貨保守假設買入費從收到的 base 扣除、賣出費從 quote 扣除，不預先套 BNB 折扣，依 [Binance 費用說明](https://developers.binance.com/en/docs/products/spot/faqs/commission_faq)。合約按多空實際買賣邊分配費率並保留資金費。ask→bid／bid→ask 價格情境已含價差，不重扣；原有含價差的風險成本預算仍完整保留。

原生 Kev 防線獨立讀取原始費率、完整成本設定、快照及 bridge 保存的 fresh execution quote，重算費用、價差、雙邊滑價、資金費與緩衝，核對 Kev 看到的成本及 entry plan。缺失、过期或成本低報都拒絕，三個送單邊界相同。此修正防止未來少算成本；不代表已證實歷史成交漏扣或改版必然盈利。證據置於 `local/kev-net-cost-2026-09-21/`，原始交易紀錄與目標不重設。

資料為每十秒 REST 五檔深度，共三份簿，以及滾動六十秒主動買賣成交流。送 Kev 的摘要涵蓋完整取樣成交流，原始最近八笔成交另行標示，原始完整證據留在本機。進場與送單前報價不讀 K 線、ATR、均線或模型預測。舊原生引擎五分鐘設定僅留作歷史策略相容，Kev 不等待它。

現貨每分鐘第 5 秒、合約第 30 秒開始，錯開單一 Codex CLI。請求上限十五秒並預留至少十秒執行；該分鐘結束即過期。沒有候選不呼叫，忙碌／逾時／格式錯誤／觀望不下單，也不重試或使用其他候選替代。這是分鐘級訂單流交易，不是逐事件或毫秒高頻。

固定退出參數：停損 0.5%、停利 1.5%、最長 900 秒；固定 3:1 毛幾何與先前 flow 路徑一致，但完全不依賴 ATR。保留淨利追蹤、1 USDT 估計壓力風險、現貨原生限價停損保留額、合約 1 倍逐倉。實際現貨費用約 30–34bps；成本後計畫報酬必須嚴格高於含成本停損風險，目標必須覆蓋完整成本與緩衝。此固定目標不代表價格預測、實際損失上限或已證明盈利。

原生 `kev-native-entry-v1` 在 callback、order context、送往交易所前檢查同一不可重用 intent。完整 Kev 決策 JSON 原始位元組雜湊、精確選項、方向、快照、原始簿／成交資料、期限、報價、成本和風險都必須相符。舊持倉讀原有數值計畫，不等待 Kev。

保留原始 session、帳務、持倉與100筆目標。`kev-order-flow-amendment.json` 綁定原 goal hash，只接納啟用時間後的真實新政策成交。批准、送出、成交、平倉分開記錄。採用 Kev 格式的 Codex CLI 服務；未載入上游 Kev 權重。
