# 提示詞 v14 修訂

更新時間：2026-09-16（台北）。本版依目前程式改善 analyst 的審閱提示詞組裝，不把提示詞當成獲利保證，也不改寫既有成交、損益、持倉、deterministic 訂單流規則或原生退出計畫。

## 改動

- `src/analyst.mjs` 將 `PROMPT_VERSION` 更新為 14。主機契約明確指定來源優先序：schema／能力矩陣、deterministic `ruleReference`、帳戶與持倉、當次市場證據、最後才是風格文字。
- 新進場遇到資料衝突、缺欄位、過期時間戳、重複識別或不支援方向時一律 HOLD，避免模型用不完整快照自行補值。
- 既有原生出場採獨立檢查：只要出場證據充分，就不能因「進場專用」成本欄位缺漏而抑制合理平倉；費用仍只由引擎結算一次。
- 帳戶、快照與規則結果用 `BEGIN_UNTRUSTED_*_DATA`／`END_UNTRUSTED_*_DATA` 明確包覆，資料內容不能改寫前面的主機契約或輸出 schema。
- `adaptiveParameters` 必須使用當次持久化值；提示詞不得從少量成交自行發明風險倍數、成本緩衝或勝率。

## 現貨空方邊界

提示詞讀取 `directionCapabilities`。目前標準 Binance Spot Demo 的 `short` 仍為 `null`，因此空方想法只能回傳 `HOLD` 與 `SPOT_SHORT_REQUIRES_MARGIN`；一般 `sell` 只代表平既有多單。只有日後另行驗證的 Margin adapter 同時提供非 null 空方動作、借幣／身分及完整執行邊界時，提示詞才會提出現貨空方。這不是把提示詞文字當成未驗證的下單能力。
