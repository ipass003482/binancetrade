# 實際 Demo 獲利品質觀測

目標：以扣費後淨利及共同本金回撤選擇策略，補齊「交易過程曾經獲利，退出時保留多少」的實際觀測。這次改善績效回饋，沿用 v6 的 5 分鐘進場與進場時保存的退出計畫，不重設策略樣本或 2,000 USDT 試驗本金。

## 本次交付

- 既有約每分鐘的成交報告更新，同時保存逐筆引擎 `profit_abs` 到 `local/<mode>/profit-observations.jsonl`。以交易 ID、完整進場標籤、交易對及開倉時間比對身分；僅記錄已核對完整的 Demo 交易。
- 觀測檔追加並同步寫入磁碟，跨監控重啟與版本更換保留。已平倉相同損益不反覆追加；後續費用修正保留新紀錄。損壞或未寫完的檔案不覆寫，報告明確顯示不可用。
- `forward-report.json.profitReview` 分開列策略與技術驗證單：已實現／未實現淨損益、已觀測持倉淨損益高點、浮盈回吐、開始觀測時間、樣本數、最大觀測間隔，以及引擎記錄費用。平倉再按退出原因彙總實際淨利及費用。
- 儀表板「本輪 Demo 實際成交」新增「獲利保留、費用與退出表現」。

## 數字的意義

1. 淨損益直接取自引擎的實際 Demo 交易記錄；不扣第二次費用。未平倉損益仍為引擎估值，不當作成交獲利。
2. 高點只取開始記錄後的持倉觀測。既有持倉開始記錄之前、以及兩次觀測之間的高低點不補算。不用 K 線最高／最低價假裝成功平倉。
3. 正的觀測高點減去目前或平倉淨損益，正差為「已觀測浮盈回吐」。沒有持倉觀測或未曾觀測正浮盈時留空。平倉淨利除以正高點的比率可能為負或超過 100%，不得解讀成最高點成交能力。
4. `observedAt` 是 API 讀取時間，不是交易所報價產生時間；分鐘內行情可能未被觀測。`firstObservationDelaySeconds` 明示進場後多久才開始記錄。
5. 引擎 `fee_*_cost` 是報價幣費用帳值；支付資產 BNB／其他幣名不能直接當計量單位。未平倉只列進場費用，費用缺漏留空；這不是獨立核對的原始交易所佣金清單。
6. 損益觀測資料的異常不會創造訂單、重送委託或改動停損；原本的交易、資金及原生保護檢查繼續生效。

## 後續 Demo 調整依據

目前 v6 為完成的 15 分鐘 ATR 決定固定停損與止盈，使用 5 分鐘訊號。先讓此版本的實際交易完成，持續記錄浮盈到平倉的變化。

待驗證的下一輪假設：若同類策略成交反覆出現正浮盈後轉虧，檢驗加入保本或移動停損能否改善扣費淨利及共同本金回撤。須事先保存新版本的觸發與退出參數，讓新交易實際執行並記錄早退後少賺及停損後反彈的代價。比較時同時看淨利、平均每筆淨利、虧損、回撤、費用、退出原因與樣本涵蓋期間，不能只挑成功交易或用高點推算獲利。若觀測不支持這個假設，就保留原退出方式或改查進場品質；不因單筆浮盈波動就重設整套參數。

每日開倉次數維持不設上限。既有 30 筆初步比較參考不構成停止交易的額度，也不構成禁止設計下一輪 Demo 試驗的門檻。
