# 提示詞 v13 修訂

更新時間：2026-09-16（台北）。本版只改善 analyst 審閱提示詞與其組裝邏輯，不把提示詞當成獲利保證，也不改寫既有成交、損益、持倉或原生退出計畫。

## 改動

- `src/analyst.mjs` 將 `PROMPT_VERSION` 更新為 13，並以現行 `strategyContract.directionCapabilities` 作為方向矩陣來源，避免提示詞和執行器各自維護一份方向能力。
- 四份風格檔統一成同一個決策順序：主機權限與 schema、deterministic `ruleReference`、帳戶／持倉、當次證據，最後才是進取或保守的候選排序。
- 加入明確的 untrusted data 邊界。帳戶、快照與規則結果放在 `BEGIN_UNTRUSTED_*_DATA`／`END_UNTRUSTED_*_DATA` 之間，資料內容不能覆蓋前面的主機契約或最後輸出規則。
- 明確要求讀取當次 `adaptiveParameters`，只使用其已保存的風險縮放、成交門檻、成本緩衝和波動輸入；不能用模型主觀數字或少量交易結果重新調參。
- 明確區分「主機選出的 action」與「審閱意見」。有 `ruleReference.proposal` 時保留主機 action、pair 與風險縮放 stake；HOLD 不能被提示詞改成進場。實際成交仍以 bridge、native guard 與交易所回執為準。
- 將成本重複計算、過期一分鐘訊號、未收 K 線、舊版技術門檻、未驗證 Margin 空方與虛構勝率列為明確 HOLD 條件。

## 現貨空方邊界

提示詞會讀取 `directionCapabilities.short`：非 null 且另有已驗證的 Margin 身分／借幣邊界時才可提出現貨空方；目前 `demo` 一般 Spot Demo 的值仍是 null，所以下行假設必須回傳 `HOLD` 和 `SPOT_SHORT_REQUIRES_MARGIN`。一般 `sell` 仍只代表平既有多單。要啟用現貨空方，需另行建置並驗證隔離的 Margin adapter，不能只改提示詞。
