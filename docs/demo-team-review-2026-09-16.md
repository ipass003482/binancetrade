## 已部署的改進

- 訂單流：主機與原生端的 55% 主動成交金額邊界改用一致的高精度比較；拒絕負成交 ID，合法 ID 0 仍接受。新現貨反向確認遇到成交／深度序號倒退時清空確認，避免舊資料延續退出證據。未更改 55% 數值、ATR、成本、風險或既有持倉計畫。
- 觀察資料：錨點分別記錄基礎訂單流、當時採樣報價延續及兩者交集；後續一／五／十五分鐘報價反應保留原分類。舊紀錄缺欄位仍為缺失，不回填。這不是下單前即時報價，不含成本／容量資格，不是成交勝率。
- 實際成交：新增按原進場政策與執行品質版本分組的淨利、勝率、平均贏／輸、獲利因子與平倉序列回撤。原 tag、journal、實際成交及金額須吻合。缺失、矛盾、未確認結果保留未知；原損益不移除。尚未平倉的新版本沒有勝率證據。
- 停損診斷：按同一原生停損委託核對原觸發價、接受量、實際成交量、方向及時間，計算不利／有利滑價。未知成交量、矛盾回執及錯誤時間不能當作零。不重扣原損益中已記錄的費用／資金費。
- 頁面新增「策略改版有沒有進步？」及停損／風險超支明細；診斷失敗明示，不假裝成功。今日損益遇到未來或倒序平倉時間拒絕完整統計。
- 部署先驗證全部來源差異，只複製已列入 hash 清單的檔案；兩模式先完成 owner／STOP 檢查再啟動，保留原倉與交易所停損。
