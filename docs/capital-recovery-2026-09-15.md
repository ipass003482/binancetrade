# 觀察器不中斷取樣與歷史資料恢復

2026-09-15 台北 22:00 更新 dashboard／鏈上觀察器，runtimeVersion=`independent-history-recovery-v1`，觀察版本及起點仍為 `capital-flow-observer-v1` / 21:03:14。部署與保留檢查在 `local/capital-recovery-2026-09-15/validation.json`。

修正兩個由程式與隔離測試確認的問題：

1. 原本取樣 tick 等待完整成交 history 回應，慢速 API 會阻塞下一筆觀察。改成獨立 single-inflight 背景成交核對；不增加並行交易讀取，不阻塞訂單流取樣。頁面分開呈現行情觀察時間與成交核對時間；成交結果超過 90 秒則不顯示舊結果。
2. 原本僅在記憶體保留最近兩分鐘資料，新成交若在 API 中斷或重啟後才首次被發現，較早的進場背景會失去歸因。現在按真實開倉時間，從原始觀察 journal 串流讀取前 45 秒完整紀錄，可跨 UTC 午夜。讀取固定已完成的 byte range、驗證尾行，避免並行 append 的不完整尾段；不載入整天資料至記憶體。只讀當時已記錄的前瞻證據，不事後查供應商歷史回填。既有每筆歸因檔仍不可覆寫。

這些是可重現的可靠度問題；未宣稱已造成實際虧損或本次修正提高勝率。最近同向 UNI71 -0.68076386、混合 SOL53 +0.87249552 保留原紀錄，不能用兩筆判定背景訊號有效。

頁面流程圖同步改為目前 Demo 的訂單流→方向→成本／風控→下單→持倉保護→實際扣費損益。鏈上與模型以虛線接入獨立觀察，沒有接到交易批准。移除架構圖內把所選 dry-run 連線狀態混作 Demo 執行狀態的文字，改顯示元件职责，並在上方加入流程圖捷徑。
