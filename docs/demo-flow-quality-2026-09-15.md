# 現貨訂單流：取樣可靠度與前瞻觀察

2026-09-15。使用者要求所有可用智能體研究現貨訂單流。主智能體整合，三個研究智能體分別核對原始研究、實際候選、執行與資料完整性。正式啟用以 `local/v12-flow-quality-2026-09-15/running.json` 及 `validation.json` 為準，不能把 staged 測試當成部署。

## 本輪證據與決定

截至 14:00 台灣時間，37 個現貨週期、370 個候選中，358 個資料有效；23 個通過訂單流，19 個被淨報酬／風險條件擋下、1 個被價格空間擋下。三個 buy 候選只有兩個提交，另一個已有同幣持倉。這批沒有時間超標造成的拒絕。詳見 [候選與成本審計](spot-flow-evidence-2026-09-15.md)、[執行審計](spot-flow-execution-audit-2026-09-15.md)、[官方文件與原始論文研究](spot-flow-research-2026-09-15.md)。

50 bps 原生風險保留對應實際 0.995 stop-limit 限價；它不是手續費，也不能直接刪除當成節省成本。提高 ATR 目標只會改变計畫比例，沒有證據使市場更常抵達目標。因此本輪保持 `order-flow-only-v1` 的 55%、三次深度同向、中間價方向、成本、風險及退出規則。

## 已實作的可靠度改善

`per-pair-clock-v2` 在每個幣對真正發出請求時推進本輪已核對的交易所時鐘，避免後排幣對沿用過早的成交窗尾。深度時間記為深度回應抵達時間，不再使用較慢成交請求的完成時間。取樣周期扣除工作時間，但兩輪至少間隔五秒，避免慢輪後立即補跑；429／418 保留完整六十秒退避。時鐘倒退、過期及 native 原有時效限制繼續拒絕。

獨立的合成慢網路測試由 9/10 有效資料改善為 10/10。它證明可靠度缺陷已重現並修正，不能稱為今天少成交主因或利潤改善。現貨與合約共用收集器，兩者套用同一時間修正；研究觀察器只處理現貨。

## 現貨前瞻觀察

`spot-flow-observer-v1` 使用當下實際 Demo 資料，記錄最佳一檔不平衡、加權中間價、買入金額占比、聚合成交集中度、三個現行流條件。每幣對最多每六十秒新增研究起點，保留通過和未通過的有效訊號；固定追蹤一、五、十五分鐘後第一個有效報價，容許遲到二十秒。缺資料標 missing，不插值、不回補啟動前資料，不加入交易筆數。

`futureBid/currentAsk-1` 是含買賣價差的假設報價反應，**不是委託成交、已實現損益或勝率**。本輪未給研究觀察器費率，因此扣額外成本欄位保持 null；不能再重複扣一次 spread。逐 horizon 保留非重疊樣本標記，不把同時段各幣或不同 horizon 當成獨立交易。

觀察寫入採獨立單一執行工作，繁忙時跳過研究取樣並記錄 `skippedBusySamples`；研究錯誤不等待、停止或改變交易決策。研究狀態損壞及 JSONL 截斷尾行會停止研究寫入並回報 unavailable，原始檔保留。重啟讀取已保存狀態；append 後 state 保存前若當機，可能重複寫入，因此唯讀報告依 deterministic recordId 去重，衝突列為缺證據。

紀錄位於 `local/demo/spot-flow-research/`。原始完整交易 snapshot、entry plan、實際委託與費用仍由既有交易流程保存；研究的 compact observation 另有來源 proof hash，不能代替成交證據。持續 Demo、原本金基期、舊虧損、今日各 100 筆目標與原模型各 30 筆歸因維持原樣。

## 後續研究邊界

四筆滿一千筆的成交窗確有截斷；本輪繼續拒絕，不取消完整性檢查。完整分頁或連續 WebSocket 深度需要新的原始證據契約與 native 重驗，列入唯一現行 plan 的後續項目。加權中間價位於 bid/ask 之間，不能新增「高於 ask 加成本」這種不可能通過的條件。未有前瞻與真正扣費成交證據前，不宣稱新特徵提高勝率。
